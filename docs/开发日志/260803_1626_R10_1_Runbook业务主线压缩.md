# 一.问题反馈

当前 DCC-first 作品集已经能在 Maya 内打开并导出 5 个模块的统一展示包，但展示逻辑仍容易被理解成“一个工具壳加 5 个并列小工具”。作品集展示需要从真实 TA 业务链路进入：一个资产如何从协议、规则、视觉、贴图到批量交付被治理起来。

# 二.⭐回顾分析

真正的高价值点不是按钮数量，而是能否把 DCC 场景中的资产交付问题拆成稳定的业务阶段，并让每个阶段都有确定性逻辑和可复查证据。

R10.1 的展示口径：

- 工具壳：Maya / AuroraView 内的 DCC 展示与证据编排层。
- 五个模块：同一条资产发布链路的业务阶段。
- 主线顺序：Author Contract -> Publish Gate -> Visual Review -> Texture Delivery -> Batch Handoff。
- 展示目标：让 reviewer 先看到业务问题和证据链，再进入具体模块按钮。
