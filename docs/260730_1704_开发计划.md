# 一.目标

> 2026-07-30 更新：作品集主线已调整为从 Lightbox 高价值业务插件中抽象 TA 方法，再用公开合成数据重制成可运行 AI 工具 demo。当前主计划见 `260730_Lightbox高价值线作品集开发计划.md`，本文保留为作品集基础结构规划。

把 `AIToolTA_Portfolio` 做成 AI 工具 TA 作品集，呈现“真实问题 -> 工具逻辑 -> AI 能力 -> 可验证结果 -> 可迁移方法”。

作品集服务两个目标：

1. 对外展示：让别人快速理解我能做什么类型的 AI 工具和管线系统。
2. 对内复盘：把已经做过的个人工具沉淀成可复用的方法库、截图/视频素材库和技术故事库。

# 二.作品集结构

建议保留四层内容：

| 层级 | 目录 | 内容 |
| --- | --- | --- |
| 总入口 | `README.md` | 定位、选题池、当前路线 |
| 案例文档 | `docs/case-studies/` | 每个工具一篇深度 case study |
| 展示实现 | `showcases/` | 后续放作品集网页、交互 demo、静态导出 |
| 视觉素材 | `assets/` | 截图、录屏、封面图、流程图、对比图 |

单个 case study 使用固定模板：

```markdown
# {工具名}

## 业务问题
这个工具解决什么真实问题，手工流程痛点在哪里。

## 核心逻辑
数据怎么进来，AI 做什么，规则/算法/管线怎么处理，结果怎么出去。

## 展示证据
可运行命令、截图、视频、样例输入输出、测试结果。

## 工程设计
目录结构、关键模块、依赖、失败处理、可扩展点。

## TA 方法
这个案例能迁移到其他 DCC / 工具管线 / 内容生产流程里的方法。
```

# 四.开发阶段

## P0. 盘点与定标

输出：

- 确认首批 3 个主案例和 2 个轻量案例。
- 每个主案例补齐 README、运行命令、样例输入输出。
- 整理已有截图/视频，缺失的列成拍摄清单。

完成标准：

- `docs/case-studies/` 下至少有 3 个 case study 草稿。
- 每个主案例都有“业务问题、核心逻辑、展示证据、工程设计、TA 方法”五段。

## P1. 作品集首页

输出：

- 在 `showcases/portfolio-site/` 建一个可本地运行的作品集首页。
- 首页展示个人定位、工具矩阵、3 个主案例入口。
- 每个案例页包含问题、流程图、截图、关键代码片段和成果。

完成标准：

- 本地可运行。
- 桌面和移动视口不溢出。
- 每个案例能在 1 分钟内讲清价值。

## P2. 主案例打磨

输出：

- 给 3 个主案例补录屏或 GIF。
- 补关键流程图和架构图。
- 增加“我作为 TA 的判断”段落，突出业务逻辑，不写成工具说明书。

完成标准：

- 每个主案例有可视证据、技术证据和方法总结。
- 每个案例都能回答：为什么值得展示，别人能学到什么。

## P3. 发布与维护

输出：

- 生成静态站点或可分享 HTML 包。
- 建立后续新增案例模板。
- 每完成一个个人工具，就补一个 case study。

完成标准：

- 作品集能独立打开浏览。
- README 能指向所有展示案例。
- 新案例有固定模板，不再临时组织。

# 五.质量门槛

每个进入作品集的工具必须满足：

1. 有真实问题，不收纯玩具 demo。
2. 有核心逻辑说明，不只展示 UI。
3. 有可验证结果：命令、截图、视频、样例输出或测试。
4. 有失败边界：说明当前做不到什么，下一步怎么补。
5. 有 TA 方法总结：这个工具背后可迁移的工程判断是什么。
