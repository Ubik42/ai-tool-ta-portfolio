# AI工具TA作品集工程报告摘要

## 当前发布状态

`AIToolTA_Portfolio` 当前已形成 DCC-first 作品集基线：Maya 2024 内通过 AuroraView 打开工具入口，React/TypeScript 仍作为嵌入式界面层，核心证据来自 DCC / 引擎 runtime、fixture、JSON artifact 和 Presenter Pack。

当前公开包为 `ai-tool-ta-dcc-first-showcase-r72` / `dcc-first-package@1.69.0`。R72 Presenter Pack 已收束 70/70 个关键证据文件、60 步 demo route、5 个主工具模块和跨 Maya / Blender / 3ds Max / Houdini / Unreal 的证据。最新增量是 `Unreal Animation Notify Native Controlled Write`：packaged `AI_Tool_TA_AnimNotifyBridge` 已在临时 Unreal 5.3 project 中把 `equip.attach` / `gear.attach` 写入 public AnimSequence，保存后 post-check 2/2 可见，再 rollback 删除并恢复 `.uasset` hash，productionWrites=0、persistentMutation=false。媒体门禁仍为 `CapturePending`，需要补 Maya GUI 截图和路线录屏。

## 可写入简历的项目

1. **AI Tool TA DCC-first 作品集**

   Maya 2024 + AuroraView + React/TypeScript 的 DCC 内嵌工具展示入口。价值不在网页壳，而在把 Asset Protocol、Rule Matrix、Visual Review、Texture Delivery、Task Orchestrator、Scene Transaction Guard 串成可演示、可导出、可审计的工具管线案例。

2. **跨 DCC / 引擎资产检查适配器**

   把 Lightbox 类 Pyblish 资产检查经验抽象成公开 fixture 和 rule contract。当前覆盖 Blender `bpy` L3、Blender controlled repair / rollback L3、3ds Max `pymxs` L3、3ds Max controlled repair / rollback L3、3ds Max material slot -> texture manifest L3-derived、Houdini HDA / PDG / bake receipt contract、Unreal L3++ handoff inspector：关注 user properties、LOD、材质槽、贴图依赖、UV、transform、collision、程序化 cook 稳定性、引擎 registry、平台 preset 和 waiver 边界。

3. **Maya 资产交付工具模块组**

   面向真实 TA 发布流程：协议写入与回读、规则矩阵、截图清单、贴图交付检查、dry-run 任务队列、资产放行决策、引擎导入 preflight、scene transaction diff 和 rollback preview。展示点是“工具修改了什么、为什么能放行、哪里必须阻断”。

4. **Animation Continuity / Unreal Animation Bridge**

   面向动画交付的业务正确性检查：Maya `mayapy` 创建并采集 keyed animCurve facts，把 rig identity、skeleton fingerprint、take range、sample rate、required channel、sub-frame key、root motion、scale drift 和 additive layer 变成可审计证据；Unreal Python 继续完成 Maya FBX 生成、AnimSequence / Skeleton 导入和 runtime facts 采集，并用 R41 deep facts 只读验证 duration、derived frame span、frame-rate、root motion、compression metadata visibility；R67 把 gameplay attach intent 接到 AnimSequence notify/timing gate，R68 把 Python notify 不可读推进为 native bridge source/readiness，R69/R72 已把 `AI_Tool_TA_AnimNotifyBridge` 编译成可加载的 Editor DLL，R70 已证明 commandlet runtime 可见，R71 已让 native commandlet 读取具体 public AnimSequence 并确认缺少 `equip.attach` / `gear.attach` notify，R72 已完成受控写入、post-check、rollback 和 `.uasset` hash restore，避免把“有 socket、有动画资产”误判为可发布，也证明工具能进入引擎内执行安全修复。

5. **Character Calibration / Spatial Authoring**

   面向角色和空间挂点交付：Maya `mayapy` 采集 topology、joint coverage、face params、Control Rig mapping，以及 socket parent joint、mirror pair、hotspot semantic、pose frame、local-space 和 pose transfer approval；R35/R36 已分别把角色和空间作者 L3 flat rows 投影成可在 Maya/AuroraView 展示的 drilldown panels、owner actions 和 fix previews，R42-R45 已把角色线推进到 public Control Rig fixture authoring、face skeleton fixture、deformation link 和 compile status；R38-R40 证明 Unreal Python socket identity 不可可靠写入，R60-R65 把缺口推进到 native bridge source/build/commandlet/receipt dry-run/controlled write，R66-R72 已把 controlled socket write 接到 gameplay attach readiness、animation timing readiness、native notify bridge readiness、native notify bridge build、native notify commandlet probe、native diagnostics 和 native controlled notify write，证明 socket 工具可以从 DCC intent 走到引擎受控执行、玩法挂接审核和动画触发门禁。

6. **Platform Variant Forge**

   面向 PC -> Mobile 资产派生：把目标路径、owner approval、triangle/texture/material/draw-call budget、LOD coverage、Nanite、shader feature、collision policy、Unreal runtime facts、材质贴图依赖事实和 public Texture2D payload 合成可审计 variant plan，并把 drift 转成 dry-run generation operations。展示点是“平台降级为什么能自动做、哪里必须阻断、引擎里实际是否达标、下一步生成动作如何受控执行”。

7. **MayaCraft AI 友好模块化绑定框架**

   独立探索面向 AI agent 的 Maya rig/tool 框架，目标是把绑定组件、参数协议、执行入口和模块组合方式结构化，方便后续由 agent 读取、调用和扩展。
