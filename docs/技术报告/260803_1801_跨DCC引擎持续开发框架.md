## 3. 下阶段核心目标

优先补一个非 Maya 或引擎真实证据点，避免作品集被理解成“只有 Maya 工具”。推荐顺序：

1. **Blender Rule Adapter L3**
   - 目标：把 Cross-DCC Rule Matrix 从 mock 推到真实 Blender adapter。
   - 最小闭环：Blender Python headless 读取合成 mesh，采集 unit/up axis/UV/material/collision-like facts，导出 rule evidence JSON。
   - 展示价值：证明共享 rule DSL + DCC adapter 不是口头设计。

2. **Unreal Engine Handoff Inspector**
   - 目标：把当前 Engine Preflight / Preset Compare 从 dry-run sidecar 推到 Unreal-side inspection。
   - 最小闭环：不写生产资产，只做 Unreal Python 或 fixture-level import intent inspector，验证 path、platform、LOD、texture sidecar、sequence binding。
   - 展示价值：证明 TA 能把 DCC evidence 接到引擎消费规则。

3. **Animation Continuity Lab**
   - 目标：建立跨 Maya / MotionBuilder / Unreal 的 identity、time、curve、channel、receipt 协议库。
   - 最小闭环：headless diff 先稳定，再接 Maya / Unreal 局部验证。
   - 展示价值：硬核动画管线能力，区别于普通资产检查工具。

4. **DCC Scene Transaction Recorder**
   - 目标：让工具运行前后对 scene state 的影响变成可审计 receipt。
   - 最小闭环：先在 Maya fixture 验证 selection/time/camera/reference/namespace 捕获和恢复，再迁移到 Blender。
   - 展示价值：展示专业 DCC 工具可信度。

5. **Character Calibration / Spatial Authoring**
   - 目标：把 DNA/topology/joint coverage、空间热点、pose transfer 从研究 fixture 变成独立工作台。
   - 最小闭环：先做协议和可视化，不直接塞进现有 Maya Host。

## 4. 每轮 Codex 循环规则

每轮只选一个可闭环任务，按以下顺序执行：

1. 读取最新 `docs/开发日志`、`docs/技术报告`、`lightbox提取` 和真实代码状态。
2. 判断本轮是否推进“跨 DCC / 引擎真实证据”。如果不是，必须说明为什么。
3. 选择一个最小增量：代码、fixture、artifact、验证脚本、宿主入口、文档证据，至少完成一种。
4. 执行验证：能跑 build / py_compile / headless smoke / JSON consistency 就必须跑。
5. 更新相关 README / manifest / module doc / public package，避免路径和版本漂移。
6. 写 `docs/开发日志/YYMMDD_HHMM_*.md`，只用四个固定一级标题。
7. 报告当前完成度、验证结果、下一轮推荐。

## 5. 任务选择阈值

优先做：

- 能把 mock 推到真实 DCC/引擎 adapter 的任务。
- 能产生可机器读取 artifact 的任务。
- 能直接支撑最终作品集演示的视频/截图/Presenter Pack 证据。
- 能体现 Lightbox 真实业务秘诀：协议、规则、确定性、事务保护、引擎交付、人工边界。

暂缓做：

- 只增加前端卡片、说明文字或边缘 owner drill 的任务。
- 只能展示 UI、没有新的确定性逻辑或证据包的任务。
- 需要复制内部资产、路径、接口或敏感规则的任务。
