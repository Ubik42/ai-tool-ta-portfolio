## 2. 循环开发节奏

每轮只闭环一个高价值业务任务，不做散点堆叠。

标准交付顺序：

1. 选一个 Lightbox 高价值业务点。
2. 写 public-safe schema / fixture。
3. 写 DCC 或 engine collector，把真实软件事实归一化。
4. 写 rule evaluation / decision / fix preview。
5. 导出 JSON artifact。
6. 接入 Presenter Pack / public manifest。
7. 同步模块文档和开发日志。
8. 跑对应档位验证。

一轮的完成定义：

- 有明确业务问题，不只是新增 UI 卡片。
- 有 fixture 或 runtime 证据。
- 有机器可读 artifact。
- 有 Presenter Pack 或 public package 可发现路径。
- 有文档说明当前 gate、边界、下一步。
