# Product

## Register

product

## Users

Primary users are tool pipeline TAs, technical artists, tech art leads, and portfolio reviewers who need to judge whether real DCC production problems have been turned into shippable AI-assisted tools.

The usage context is evaluative and practical. Users inspect tool logic, rule systems, fixture data, UI behavior, report payloads, and evidence artifacts.

## Product Purpose

This Vite app is the runnable product workbench for the AI Tool TA portfolio. It turns high-value Lightbox plugin patterns into public synthetic modules that demonstrate business logic, deterministic execution, AI-assisted diagnosis, and production-style evidence.

Success means each module can answer these questions quickly:

- What real production problem does this solve?
- What is the core business logic?
- Where does AI help without weakening deterministic rules?
- What evidence proves the tool works?

## Brand Personality

Calm, technical, concrete.

The product should feel like a senior TA's internal toolbench: dense, inspectable, traceable, and confident. The tool logic should carry the impression.

## Anti-references

- Generic AI portfolio landing pages with oversized slogans and decorative gradients.
- Tutorial-style demo pages that explain features instead of exposing working controls.
- Toy widgets that do not model real DCC production constraints.
- One-off visual showcases that cannot be extended into repeatable production tools.

## Design Principles

- Show the workbench first: the first screen is a usable product surface, not a marketing hero.
- Treat rules as product: schemas, fixtures, severity, fixes, reports, and diffs are first-class UI objects.
- Keep AI subordinate to production truth: AI explains, drafts, clusters, and diagnoses; deterministic code owns final state.
- Make every module independently legible: each tool needs its own problem, data model, interaction loop, and proof artifact.
- Build a platform, not scattered demos: shared shell, shared fixtures, shared report patterns, and shared evidence format.

## Accessibility & Inclusion

Target WCAG AA contrast for text and interactive controls. The product should work with keyboard navigation, visible focus states, reduced motion preferences, and color-independent status labels.
