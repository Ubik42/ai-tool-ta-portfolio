# Product

## Register

product

## Users

Primary users are tool pipeline TAs, technical artists, tech art leads, and recruiters or reviewers who need to understand whether the author can turn real DCC production problems into shippable AI-assisted tools.

The user context is practical and evaluative: they are not browsing a marketing site, they are inspecting tool logic, rule systems, data models, UI behavior, and evidence that the work can survive real asset production.

## Product Purpose

This product is a portfolio workbench for AI Tool TA capability. It turns high-value Lightbox plugin patterns into public, synthetic, runnable modules that demonstrate business logic, deterministic execution, AI-assisted diagnosis, and production-style evidence.

Success means each module can answer four questions quickly:

- What real production problem does this solve?
- What is the core business logic?
- Where does AI help without weakening deterministic rules?
- What evidence proves the tool works?

## Brand Personality

Calm, technical, concrete.

The product should feel like a senior TA's internal toolbench: dense, inspectable, traceable, and confident. It should avoid portfolio theatrics and let the tool logic carry the impression.

## Anti-references

- Generic AI portfolio landing pages with oversized slogans and decorative gradients.
- Tutorial-style demo pages that explain features instead of exposing working controls.
- Toy widgets that look interactive but do not model real DCC production constraints.
- One-off visual showcases that cannot be extended into repeatable production tools.

## Design Principles

- Show the workbench first: the first screen should be a usable tool/product surface, not a marketing hero.
- Treat rules as product: schemas, fixtures, severity, fixes, reports, and diffs are first-class UI objects.
- Keep AI subordinate to production truth: AI explains, drafts, clusters, and diagnoses; deterministic code executes final mutations.
- Make every module independently legible: each tool needs its own problem, data model, interaction loop, and proof artifact.
- Build a platform, not scattered demos: shared shell, shared fixtures, shared report patterns, and shared evidence format.

## Accessibility & Inclusion

Target WCAG AA contrast for text and interactive controls. The product should work with keyboard navigation, visible focus states, reduced motion preferences, and color-independent status labeling.
